# 独立员工/管理员业务端

业务端位于完整 GitHub 仓库的 `business/`，与 `packaging-library/` 同级。仅安装 Skill 时不一定包含它；先定位用户下载的完整仓库，缺少时获取完整仓库副本，不读取原作者的业务目录。

1. 先读 `business/README.md`。检查 Python 3.12、Pillow/openpyxl/defusedxml；Node 24 用于服务端分页。由你准备环境。
2. 使用 `python business/run_demo.py` 在本机启动。它生成两套随机账号并正常执行登录与权限校验，监听固定为回环地址。让使用者在本机查看 `.runtime/accounts.json`，不要把密码写进公共文档、提交或聊天。
3. 从 8 条虚构记录开始验证。用户的海报与风格足以启动展示项目，但不足以生成真实报价、供应商、MOQ、库存或实测规格；这些未知字段保持空白，待用户提供业务资料。
4. 保留员工/管理员/客户三类服务端权限、CSRF、审计、会话撤销和编辑版本检查。不能把“切换演示岗位”当作真正的账号授权。
5. 用员工验证搜索、收藏、对比和 CSV；用管理员验证产品编辑与重新载入后保存；客户账号必须无法读取内部目录、供应商、报价或原始私有图片。
6. 运行 `cd business && python -m unittest discover -v`，再做桌面与窄屏浏览器验证。图像检索缺少权重和索引时列为未启用；订单/配方/仓库/回款页面是刷新重置的流程演示。
7. 展示前端和业务端是两个可独立运行的底座。本版不自动把海报、3D 和业务 SKU 同步。若明确要求联通，先建立稳定 ID 映射与客户字段投影，再实现授权接口；不能直接公开业务数据库。
8. 默认本机演示。已授权公开代码时，只发布源码和 `demo/`，检查 Git 忽略规则及实际提交文件；不要发布 `.runtime`、`state`、`private`、账号、会话、数据库和上传原件。正式服务使用 HTTPS 与 `server.py`，不要把 `run_demo.py` 通过隧道公开。
